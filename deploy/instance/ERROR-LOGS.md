# 产品调用报错

管理员在后台的「用量日志 → 调用报错」查看模型调用失败，页面路由为 `/usage-logs/errors`，部署在 `/harness` 前缀下时保留该部署前缀。页面固定查询错误类型，普通用户不能进入或读取管理员日志。

每条记录展示发生时间（精确到秒并显示时区）、用户、请求模型、渠道、HTTP 状态、请求 ID 和详细原因。支持时间、用户、模型筛选；长错误在详情弹窗中查看。后台使用现有 `GET /harness/api/log/?type=5` 管理接口，没有新建日志表。

## 记录范围

- 请求分发、参数校验、无可用渠道及 Relay 提前失败。
- 上游调用失败，包括最终响应前已记录的重试尝试；同一尝试不会在错误响应时重复记录。
- HTTP 200 响应头发出后的流式协议、解析或传输失败；正常结束和用户主动取消不记作上游故障。
- 视频等异步任务提交、查询和最终失败，以及超时；异步终态由状态转换成功的一方记录，关联原提交的请求 ID、用户、模型和任务号。

记录路径不主动采集完整调用请求或提示词。错误中常见密钥、授权头、凭据字段、URL 用户信息与签名查询值会脱敏。管理员保留技术原因；普通用户的错误日志列表及导出只返回「服务器繁忙，请稍后重试」及安全的请求关联信息，历史流式错误详情也不再向用户日志接口公开。

## 发布与开关

`ERROR_LOG_ENABLED` 默认开启，环境显式设置 `false` 时仍关闭。现有部署必须发布新代码后才能获得新增页面和补齐的记录路径；关闭开关的部署需要由管理员启用。不会补写此前未保存的错误。历史缺少上游任务号的批量坏任务修复路径保持原有行为。

桌面产品需要发布包含友好错误展示的新版本。产品不会更改原始 Session、工具结果或模型输入中的诊断；专用错误行和媒体失败卡使用安全提示，固定生成流程要求助手不向用户复述平台原始错误。用户主动进行的软件调试、本地终端和文件操作诊断仍按原有工作方式提供。
